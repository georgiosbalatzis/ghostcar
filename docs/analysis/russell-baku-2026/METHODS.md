# Reproducing and interpreting the Baku study

The main article compares Russell #63, OpenF1 session 11373, laps 21 and 25. Lap 20 is a completed slower preparation lap, explicitly disclosed in the Greek report; the phrase “first valid timed lap” alone does not uniquely mean lap 21. The pole is the third **push** lap, not the third row or third completed timed circuit. No other driver is used as a comparison entry.

Run from the repository root, without live network access:

```sh
node scripts/analyze-russell-baku-2026.mjs
python3 -m venv /tmp/ghostcar-baku-2026-venv
/tmp/ghostcar-baku-2026-venv/bin/pip install numpy==2.5.4 matplotlib==3.11.2 pillow==12.3.0
/tmp/ghostcar-baku-2026-venv/bin/python scripts/plot-russell-baku-2026.py
node --test test/russell-baku-2026.test.js
```

Generated JSON/CSV results and `figures/` are ignored by Git and regenerated by these commands. Captured inputs, scripts and reports remain in the repository. For the application's selectable SVG/PNG exports and turn-based iframe controls, see [Analysis figures](../../analysis-figures.md).

Python dependencies are isolated outside the repository; package.json and package-lock.json are unchanged. Raw responses were fetched with the repository's API functions and `loadReplayStreams`; the manifest records each exact URL and capture time. Traffic and historical circuit markers were obtained separately and their URLs are also recorded. Refreshing a response is an explicit new capture, not part of offline reproduction. Identity assertions stop if the selected times change. Raw JSON preserves the provider's field values; whitespace/key ordering is not an assertion about original wire bytes.

**Implementation audit.** `useComparisonSelectors.js` has independent per-slot lap state and restore logic; `ComparisonBuilder.jsx` offers the whole driver list in each slot. `uniqueDrivers` deduplicates the available driver catalogue, not the selected comparison slots. `useReplayLoader.js` and `services/openf1.js` key returned streams by slot. API metadata cache keys include all query parameters; location and car data are uncached by default and include different absolute date bounds for these two laps. `replayModel.js`, `gap.js`, `TrackMap.jsx` and the sector/telemetry components work by slot. Same driver numbers therefore do not collide. Team-colour variants and identical RUS labels are less clear for an article; standalone figures explicitly identify attempts and use gain/loss colours. No production fix is needed. The season comparison's distinct-driver use case was not changed.

**Position geometry and clocks.** Use `gap.js` directly on real x/y ground-plane coordinates, in the original common frame. OpenF1 coordinates are decimetres. Arc length is computed along the first lap, including the same endpoint estimates as `gap.js`, then converted to metres. Each other lap's samples are projected onto that reference with the existing forward search. This is not independent lap-distance normalisation and not timestamp matching. Elevation z is validated but not included in 2D arc length. The measured polyline length is 5960.616479759023 m; it is not scaled to a nominal circuit length.

Raw times are from each lap's own `date_start`, checked strictly before calling `buildTimeIndex` so its missing-date fallback cannot create timing samples here. `buildGapTrace` anchors start/finish to official times, estimates the L21 location clock offset −0.017616077 s, and subtracts it (a +0.017616077 s correction to location elapsed times). It leaves telemetry timestamps unchanged. No sample values or timestamps in raw files are mutated. Endpoint anchoring is an explicitly declared model constraint, not independent measurement of the last metres. The sampled location endpoints are 0.077/0.264 s after the start and 0.056/0.062 s before the official finish, respectively. Telemetry coverage starts at 0.080/0.068 s and ends 0.233/0.018 s before the finish. No speed value is invented at the finish. The following lap's `date_start` overlaps the calculated finish by 0.058 s (L21) and 0.159 s (L25); the API feeds are not a single exact crossing clock.

At pole-sector crossings, the common reference distances are 2004.917318722768 and 4015.246241588827 m. Computed cumulative gains are approximately 0.669039 and 0.964961 s versus official 0.649 and 0.985 s. Residuals ±0.020039 s pass the existing 0.100 s gate. The official sector sum and final gain reconcile within 1e-9 s. This gate checks two checkpoints after fitting a constant offset; it is not an independent pointwise uncertainty estimate. It does not justify calling small 10–50 ms fluctuations genuine driving gains/losses.

**Arithmetic and rendering.** Use 2001 spatial grid points and the unsmoothed time profiles for arithmetic. The `gap.js` moving-average display series is deliberately not used for the tables. `gain(s) = t21(s) − t25(s)`; each interval's gain is the difference between its two cumulative gains. Disjoint intervals sum to 1.187 s, while T20–finish is a subset of T16–finish. Displayed three-decimal segment values sum to 1.186 s due to rounding; the full-precision CSV sums to 1.187 s. In map A, colour is incremental gain over non-overlapping 200 m bins (the last bin is 160.616 m), with grey below |0.020 s|, and intensity saturated at |0.25 s|. It never uses driver/team dominance colours. The 20 ms neutral threshold is a display convention, not a claim about measurement accuracy. Chart B and chart C show the actual unsmoothed position-derived progression, including its noise and final anchor effect.

Numeric speed/throttle values at chosen distances are linearly interpolated in each lap's observed telemetry time range; missing channels stay missing. Gear and brake are discrete. Traces use native observed sample positions, and the 200 m acceleration estimates are changes in measured speed divided by elapsed time, not engine/energy measurements. DRS has zero non-null values. No unknown DRS state is drawn as closed. The late delta decline at the finish is not evidence of lifting: speed remains higher on the pole lap, and raw throttle/brake do not show such a manoeuvre.

**Corner limits.** MultiViewer `/circuits/144/2026` actually returns `year:2022`. Only approximate corner positions are used, after checking their order and their residuals (maximum 1.902 m) against current OpenF1 geometry. No old distance values are reused. Every exit proxy is projected marker +50 m. T16 marker/exit are 4064.6616/4114.6616 m; T20 marker/exit are 4960.3619/5010.3619 m. Scan every 1 m from marker +0 to +100 m to report boundary sensitivity. The resulting ranges are 0.090682–0.220854 s (T16) and 0.005798–0.097801 s (T20). They are not confidence intervals and do not include every source of position or map error. Reversing the reference to L25 changes the selected central estimates by 0.000021 and 0.000082 s, respectively; this is a limited coordinate-reference check only.

**Traffic.** Fetch only two windows, lap-start +70 s to lap finish, for all cars. For every observed Russell position in the final run, interpolate another car only between bracketing timestamps no more than 1.2 s apart; project to the shared reference. Keep candidates within 1000 m ahead, lateral residual <15 m and heading cosine >0.8. Distances wrap around the same start/finish. Static garage points and cars moving in the opposite direction are excluded by the movement test; these thresholds are disclosed heuristics. The frozen #6 laps and pit records provide additional context: during Russell L21, Hadjar completes a pit-out lap and starts his next lap at 12:56:20.843 UTC; during Russell L25, Hadjar completes a 103.500 s push lap and starts his next lap at 13:03:56.301 UTC. No pit entry is recorded inside the traffic windows. This difference in the preceding car's lap phase is an additional confounder. His separation is smaller on the pole run. #43 is a more distant candidate on the pole run. These observations support physical plausibility only: they do not measure aerodynamic benefit or a time credit caused by a tow.

**Validation scope.** Added Node tests use the real snapshot for identity, same-driver restore/requests and loader isolation, shared-distance sign and sector/finish reconciliation, reference sensitivity, explicit rejection of missing/reversed timestamps, missing coordinates/speed and incomplete lap coverage, and the frozen-response SHA-256 hashes. Missing DRS remains null. Existing tests run too. Figures were rendered at 300 dpi, inspected visually, and checked for exported sizes. The original study required no production fix. The subsequently added application exports and turn-based embeds have separate Node and browser coverage described in [Analysis figures](../../analysis-figures.md). Production builds preserve the existing GLB; Vite reports shared-import and Three.js chunk-size warnings.
